## 账务模型与根因

当前是按日投影、可合并多日确认的转账模型。付款方标记与收款方确认分离；确认记录保存方向、金额、日期分配和冻结依据，是用户确认的历史事实，并非支付平台验真的银行流水。

原日保持已结清本身不是错误。原消费净额变化后，差额进入后续未结清日期；不删除原付款。缺少差额去向展示，以及撤销被依赖付款时没有限制，会造成误解或单日方向错误。

## 已修复

| 问题 | 修改及核心文件 |
| --- | --- |
| 撤销依赖付款导致单日方向反转 | `api/v1/ledger.py` 返回 409 PAYMENT_DEPENDENCY，列出需先撤销的后续日期。已有付款不自动级联撤销。 |
| 每次确认复制整趟商品明细 | 新付款使用 freeze_basis + basis_currencies；新历史确认使用 id/revision 引用及紧凑金额依据。`core/ledger.py` 继续兼容旧 basis_expenses。 |
| 历史分次付款依赖 | 70+30 等分次付款最终冻结时记录依赖，不能撤销前一笔却保留依赖它的结清。 |
| 修改已结清消费后看不到差额去向 | 日账单新增差额转入日期及跳转；汇总继续采用服务端结果。金额、付款人、比例、实际扣款汇率、净额不变及元数据修改均补测。 |
| 草稿超时重试重复新增 | `expense/index.js` 为同一草稿保留请求键和账单 ID；成功才更换，错误重试不会生成另一笔。同一请求键的内容冲突仍由服务端拒绝。 |
| 外币实际扣款混入另一组结算 | 新消费保持旅行结算币种，单独保存 actual_payment.currency 和 payment_to_settlement_rate，界面要求填写扣款币种到旅行币种的汇率。旧账原有币种仍兼容读取，不自动改写。 |
| 历史确认绕过收款方 | monetary history preview/confirm 允许成员中的收款方；付款方不能确认收款。历史初始化及 unpaid 管理仍仅创建者可用。混合方向不能由一人统一宣布全部已付款，应分方向确认或使用普通确认流程。 |
| 昵称实际是全局昵称 | trip_members.nickname 独立保存，新增 PATCH /v1/trips/{trip_id}/members/me；请求身份限定本人。读取回退全局昵称，历史记录按稳定 ID 解析最新名称。 |
| 头像按左右位置着色、只取名字末字 | 当天账单和消费分摊按当前成员 ID 着色；头像用首字，方向及明细显示完整昵称；中性付款卡背景不随状态覆盖。 |
| 缓存昵称 | 日账单、旅行详情重新进入会读取成员；消费页返回前台仅刷新成员名称，不覆盖正在编辑的金额。 |
| 清理失败阻塞后续条目 | receipt_cleanup.attempts 记录失败次数，优先处理尝试较少的条目；前 20 条永久失败不会饿死后续条目。 |
| 客户端时区改变结算边界 | 新旅行固定创建时 UTC 偏移，离线旅行同步保留原值。旧旅行不回填；创建者补设一次，之后不可变。未补设旧旅行暂停结清，双方不再各用手机时区决定能否付款。 |

## 数据库及发布顺序

CloudBase PG 先应用：

1. `20261101020000_trip_nickname.sql`：成员昵称、清理尝试次数。
2. `20261101030000_calendar_orphans.sql`：固定旅行时区、图片创建时间、服务角色专用创建/时区/孤儿清理 RPC、含时区的快照。
3. 部署配套后端，再验证新版小程序。只更新小程序不能验证新增接口。

直接数据库/Alembic 环境对应 `20261101_10`、`20261101_11`；不要与 CloudBase SQL 重复应用。SQLite 保留时间列采用表重建，已验证含旧图片和任务的迁移不丢记录。

UTC 偏移固定，不是 IANA 地区时区；不会随夏令时自动变化。旧图片缺少可信上传时间，从迁移时重新保留 30 天，避免猜测年龄误删。

## 小票清理操作

默认没有自动孤儿删除任务。先运行：

```
uv run python -m app.worker.receipt_orphans --preview backups/receipt-orphans.json
```

人工审查清单后才运行：

```
uv run python -m app.worker.receipt_orphans --apply backups/receipt-orphans.json
uv run python -m app.worker.receipt_cleanup
```

清单含私有对象信息，保留在已忽略的 backups 目录，不提交远端。最多预览 1000 张，分批执行。应用时再次检查年龄、消费引用和 queued/processing 任务，并锁定旅行、图片及任务，防止预览后保存或识别重试产生竞态。处于 queued/processing 的长期卡住任务仍需单独排查，不为清理而强制终止。
