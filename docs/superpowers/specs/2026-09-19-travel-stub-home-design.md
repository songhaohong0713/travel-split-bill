# 旅行存根首页设计

## 目标

将首页从单一的新建表单改为“继续最近旅行”的入口，同时保持快速创建新旅行的能力。

## 视觉方向

延续旅行票据簿：米色纸张背景 `#F4EFE5`、票据白 `#FFFDF8`、墨绿 `#123E45`、金额与关键强调使用橘棕 `#C86D45`。最近旅行以整张可点击的旅行存根呈现；除新建入口外不使用装饰性卡片。

## 数据与边界

- 使用现有 `GET /v1/trips` 获取当前用户的旅行。
- 使用现有 `POST /v1/trips` 创建旅行。
- 不新增后端路由、数据库字段或历史消费统计。
- 每条旅行显示名称和默认币种；点击后进入现有账单录入页，并带入 `tripId` 与币种。

## 页面结构

1. 顶部：标题“我的旅行”，副标题“下一笔，记到哪段旅程？”。
2. 最近旅行：标题“继续记账”，按接口返回顺序展示旅行存根。每张存根左侧是名称，右侧为币种，底部提示“继续录入消费”。
3. 空状态：当无旅行时，说明“还没有旅行账单”，并直接呈现“创建第一段旅行”操作。
4. 新建旅行：已有旅行时默认收起，用户点击“新建一段旅行”后展开名称和币种表单。创建期间按钮显示加载态，防止重复提交。

## 交互与状态

- 页面加载时先完成微信登录，再请求旅行列表；加载失败时显示可理解的错误提示并保留新建入口。
- 点击旅行存根直接导航至 `/pages/expense/index?tripId=...&currency=...`。
- 新建旅行成功后直接导航至新旅行的账单录入页。
- 旅行名称为空时显示“请输入旅行名称”。

## 验证

- `listTrips` 客户端请求 `/v1/trips`。
- 首页加载成功后写入旅行数据；点击旅行构造正确的录入页地址。
- 空旅行数据展示空状态钩子；新建表单可展开。
