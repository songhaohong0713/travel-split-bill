# 旅行消费记录与紧凑条目设计

## 目标

将一段旅行中的账单从单张总账单改为多笔独立消费记录。每笔消费可含多个商品条目，仍只支持两位同行人共同编辑。

## 使用流程

1. 用户进入一段旅行，先看到消费记录列表。
2. 点击“新增消费”后，创建一笔默认名为“<当日日期>消费”的记录，并进入编辑页。
3. 用户可改消费名称、付款人、日期并录入多个商品。
4. 每个商品默认以紧凑两行显示：名称与金额在首行，分账方式在第二行；点选后才展开比例、删除等详细操作。
5. 结算页汇总该旅行的全部消费记录。

## 页面边界

### 旅行详情页

- 展示按时间倒序的消费记录：日期、名称、付款人、总额、商品数。
- 提供“新增消费”和“邀请同行人”。
- 邀请使用微信原生转发，加入者可以编辑全部消费。

### 消费详情页

- 编辑一笔消费的基础信息与商品条目。
- 使用现有批量分账、税额、优惠和结算预览能力。
- 商品列表不再以大卡片重复占用空间；详情按需展开。

### 结算预览页

- 读取旅行下的全部消费记录并统一计算转账建议。

## 数据与接口

- 复用现有 `expenses` 记录、一段旅行下的消费列表、创建和更新接口。
- 消费标题保存在既有消费 payload 中；默认标题由前端按当天日期生成，允许编辑。
- 不增加数据库表、第三方依赖或新的权限角色。

## 异常与空状态

- 没有消费时，旅行详情显示引导与“新增第一笔消费”。
- 保存失败时保留编辑内容并给出明确提示。
- 邀请链接失效、被使用或已满两人时，显示不可加入的原因。

## 验收

- 一段旅行可创建、查看和编辑多笔消费。
- 单笔消费可保存多个商品并采用紧凑展示。
- 结算汇总全部消费。
- 两位成员均可编辑各笔消费；第三人不能加入。
