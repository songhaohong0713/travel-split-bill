# 旅行票据簿界面设计

## 目标

重新设计小程序的账单录入页与结算页，让两人旅行分账的过程更易扫读、录入与核对，同时保留现有的多商品、批量分账、税费调整、OCR 附件和结算分享能力。

## 用户与场景

用户在旅行或共同消费后，根据纸质或电子小票逐项录入商品。用户需要迅速判断每项由谁承担，再生成最少转账次数的结算结果。

## 视觉方向：旅行票据簿

页面以“票据被收进旅行账本”为隐喻：背景是淡纸张色，内容是清晰的票据白，商品条目像可以勾选与归类的独立票据。页面避免贴纸、过量渐变和无意义装饰；票据条目本身是唯一的记忆点。

| 角色 | 颜色 |

## 页面结构

### 账单录入页

1. 顶部账本摘要：标题“本次账单”，显示当前两位参与人，付款人和同行人可直接编辑。
2. 小票入口：以次级操作放在摘要后；OCR 状态和候选内容收在“票据附件”折叠区域，避免干扰手动录入。
3. 商品条目：每项是独立票据卡，包含勾选状态、名称、金额和可读的分账方式。自定义比例仅在需要时展开。
4. 批量规则条：显示已选商品数，并将规则应用到已选商品。它与逐项编辑在视觉上隔开。
5. 账单调整：税费、优惠和退款收纳在低优先级区域。
6. 底部固定操作栏：实时展示应付总额，并提供唯一主操作“保存并查看分账”。

### 结算页

1. 头部显示“结算单”与账单总览。
2. 每笔转账呈现为一条清晰的结算指令：付款方、收款方、金额。
3. 无转账时显示“已经结清”，并说明两人无需再操作。
4. 发布与创建分享链接留在结算单下方，作为后续动作，而不是抢占金额层级。

## 交互与状态

- 条目被勾选后，批量规则条显示选中数量；未选中条目不受批量操作影响。
- 删除按钮只在商品多于一条时可用，避免空账单状态。
- 主按钮在保存期间显示加载态并禁止重复点击。
- OCR 上传失败的错误信息明确说明可继续手动录入。
- 表单校验错误紧邻问题区域或通过清晰提示说明需要补齐的字段。

## 可访问性与适配

- 所有文本与背景对比度满足常用移动端可读性。
- 可点击区域至少保持常用小程序触控尺寸。
- 保持单列结构，适配窄屏设备；金额不折行。
- 不添加自动播放动画，状态变化通过选中颜色、文本与加载态反馈。

## 不在本次范围

- OCR 服务端识别链路与存储/队列部署。
- 三人及以上参与人的分账界面。
- 账单历史列表与数据统计。
