# 旅行账单走查修复设计

## 目标

修复真机走查中发现的删除、连续编辑、个人消费、外币预估和账单调整输入问题，保持现有两人旅行和按消费结算的结构。

## 范围

### 删除与权限

- 仅旅行创建者可删除旅行或其中任一消费。
- 删除旅行前二次确认；确认后永久级联删除其消费、邀请和结算版本。
- 删除单笔消费前二次确认；删除后返回旅行详情并刷新消费列表。
- 同行人不能看到或调用删除入口。

### 连续编辑

- 消费保存成功后，录入页以接口返回值更新本地 `expenseId` 与 `revision`。
- 后续编辑继续更新同一条消费。
- 数据库返回 `TSB_REVISION_CONFLICT` 时，后端转换为 HTTP 409；前端提示“内容已被更新，请刷新后重试”。

### 个人消费

- 同行人字段可留空。
- 留空时，所有商品和个人调整均分配给付款人；不要求填写分账比例。
- 填写同行人后，恢复现有同行人购买、均分和自定义比例选项。

### 外币预估

- 账单币种与结算币种不同时，使用现有参考汇率显示即时预估，例如 `6155 JPY ≈ ¥261.87 CNY`。
- 预估值不写入账单；填写实际支付金额后，实际支付金额用于结算并优先展示。

### 账单调整

- 税额与优惠/退款采用完整高度的独立输入行，避免受底部固定操作栏影响。

## 接口与数据

- 新增 `DELETE /v1/trips/{trip_id}` 和 `DELETE /v1/trips/{trip_id}/expenses/{expense_id}`。
- 两个删除接口均在服务端验证旅行创建者身份。
- 复用现有 `revision`、旅行成员、汇率查询和消费 payload，不新增表、依赖、回收站或审计系统。

## 异常与验证

- 删除未授权资源返回 403；不存在的资源返回 404。
- 真正的并发编辑冲突返回 409，不再泄漏为 500。
- 最小自动验证覆盖：创建者删除权限、连续保存版本同步、个人消费、参考汇率预估和调整字段输入。

## 非目标

- 不提供恢复已删除数据、操作审计、多人角色配置或单件商品独立汇率。
