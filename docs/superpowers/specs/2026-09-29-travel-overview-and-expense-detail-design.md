# 旅行总览与消费详情设计

## 目标

把当前“旅行账本 → 可编辑表单”的单一动线，调整为 PRD 定义的三层：旅行总览 → 已保存消费详情（默认只读）→ 主动编辑。新建消费仍直接进入编辑态。

## 复用策略

- 不增加数据表、后端接口或新页面路由。
- `trip-detail` 升级为旅行总览，继续复用已加载的消费记录。
- `expense` 根据是否有 `expenseId` 和编辑状态渲染详情或现有表单；避免建立第二套数据模型。
- 结算预览继续调用现有接口，不重新实现金额算法。

## 旅行总览

1. 顶部保留旅行名称和币种，增加旅行总消费主金额。
2. 显示“已记录 N 笔消费”和最近消费日期；不把“录入者”作为主要金额指标。
3. 当消费能生成结算预览时，展示双方实际支付、应承担和当前待结算；数据不完整时展示明确的“补全同行人/汇率后可结算”提示，不显示猜测金额。
4. 消费卡片展示标题、日期、总额、付款人和商品数；点击进入只读详情。
5. 两个主入口保留：拍小票记录、手动录入；邀请和删除旅行沿用已实现权限。

## 已保存消费详情

1. 默认只读，不出现输入框、批量操作、税费折叠表单或保存按钮。
2. 顶部信息：标题、日期、消费总额、原币种、付款人。
3. 结算信息：实际支付优先；否则展示汇率换算预估；明确原币、结算币与汇率日期。
4. 商品采用紧凑账本行：商品名、金额、承担方式。税费/优惠只在存在时显示。
5. 底部仅提供“编辑此笔消费”；具备管理权限时提供删除。编辑后切换到现有完整录入表单。

## 编辑与新建

- 带 `expenseId` 打开时先展示详情；用户点编辑才加载可写表单。
- 没有 `expenseId` 时仍是当前录入页面，包含本机草稿和小票识别。
- 录入保存完成后返回旅行总览，避免再次直接进入编辑表单；用户可从总览点进详情。

## 异常与边界

- 不完整的旧数据仍可查看；缺失金额显示“待补充”，不参与总览结算。
- 多币种合计只在存在可靠的结算币/实际支付/汇率时展示；否则按原币分组或提示待补全。
- 受邀成员的编辑/删除权限仍由服务端控制；页面只改善入口显示，不承担安全判断。

## 验收

- 点击已保存消费，默认不出现可输入控件。
- 点击编辑后才可改商品、付款人、金额和分摊。
- 新建消费不受影响，仍直接录入并保留草稿。
- 总览可区分总消费、实际支付、应承担与待结算；无法可靠计算时不伪造金额。
