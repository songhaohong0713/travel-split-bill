# 双人多商品账单与批量分账设计

## 目标

将当前“单条商品 + 仅结算预览”的页面改为可保存的双人账单工作台：用户可录入多条商品，批量选择商品设置分配规则，再保存账单并生成结算预览。

## 范围

- 本期只支持两名参与人：付款人和同行人。
- 一张账单包含任意数量的商品条目。
- 商品支持四种规则：付款人承担、同行人承担、两人均分、自定义比例。
- 可勾选多条商品批量修改规则；单条商品修改会覆盖批量规则。
- 税费与优惠/退款属于整张账单，保存时同账单条目一起持久化。
- 点击“保存账单并查看分账预览”必须先创建消费记录，成功后才跳转结算页。

## 页面流程

1. 用户填写付款人、同行人与账单币种。
2. 用户添加商品行；每行含商品名称、金额和分配规则。首行默认存在，可继续添加或删除。
3. 用户勾选一个或多个商品，选择批量分配规则；自定义比例显示付款人/同行人百分比输入，并要求合计 100%。
4. 用户设置可选的账单级税费、优惠/退款及其归属。
5. 点击“保存账单并查看分账预览”。前端将完整账单写入 `POST /v1/trips/{trip_id}/expenses`，并在成功后以已保存数据请求结算预览。
6. 结算页显示转账建议，并可发布结算版本。

## 数据与接口

消费记录继续使用现有 `expenses.payload_json`，避免新增数据库表。payload 中包含：参与人、支付金额、商品列表、每项 allocation、税费和调整项。新增前端 API 调用以创建消费记录并附带 UUID 格式的幂等键。

结算预览的输入改为由已保存的账单 payload 生成；不会再出现“预览成功但账单不存在”的状态。

## 校验与错误处理

- 金额必须为正数；优惠/退款可为负数。
- 同行人不能为空且不能与付款人同名。
- 每个商品必须有名称、金额与有效分配规则。
- 自定义比例必须为两个非负数且总计 100%。
- 保存失败时留在当前页面，保留用户填写内容并显示服务端错误。
- 保存成功后才允许跳转预览页。

## 验收标准

1. 可在一张账单中保存至少三条商品。
2. 可批量勾选两条商品并应用两人均分。
3. 可将其中一条改为同行人 100% 承担，且不影响其他条目。
4. 保存后重新获取行程消费记录可看到该账单。
5. 预览结果基于已保存账单；两人存在净额差时显示正确转账建议。
