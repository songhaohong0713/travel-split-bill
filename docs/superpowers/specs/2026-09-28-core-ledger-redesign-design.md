# 核心记账流程前端重设计

## 范围

本次只重设计核心记账流程：旅行详情、单笔消费录入、结算预览。
邀请、OCR 服务、数据模型和后端接口不改；现有二人协作、自动识别、批量分账能力继续保留。

## 目标

- 一段旅行可以清楚浏览多次消费。
- 一次消费可以高效录入和修改多件商品。
- 小票识别是默认入口，但手动录入始终可用。
- 长商品清单不被重复卡片分散，金额、分配与小计易于核对。

## 视觉语言：旅行账本

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| 墨青 | `#143E47` | 正文、标题 |
| 深青绿 | `#124954` | 顶栏、主操作、小计区 |
| 纸感米白 | `#F6F4EC` | 页面底色 |
| 薄荷灰绿 | `#E8F0EB` | 识别成功、已确认区域 |
| 陶土橙 | `#D06A42` | 金额、待处理提醒 |
| 雾灰 | `#718186` | 次要信息 |

沿用小程序系统字体。标题使用较紧凑的粗体；金额使用稳定的数字对齐方式。圆角只用于有明确容器边界的消费卡、票据状态和主要按钮；不为每一行商品单独创建卡片。

## 页面结构

### 1. 旅行详情：消费卡片流

```
旅行标题 / 成员 / 汇总
└─ 按日期分组
   ├─ 消费摘要：商家 | 总额
   │            时间 · 条目数 · 付款人
   │            一行商品摘要 · 分账状态
   └─ 消费摘要 …

固定主操作：拍小票，记录消费
```

旅行详情以“一次消费”为最小单元，默认只展示摘要。点击摘要卡进入对应的单笔消费页，不在详情页内展开完整商品列表。没有消费时，空状态只保留一个明确的录入行动。

### 2. 单笔消费：小票优先的账本行编辑器

```
返回旅行
商家 / 时间 / 付款人 / 币种
票据附件：已识别 N 项
商品条目（N 项 · 批量编辑）
┌──────────────────────────────┐
│ 名称                 金额  › │
│ 分配方式                     │
├──────────────────────────────┤
│ 当前编辑的条目：名称、金额、分配 │
├──────────────────────────────┤
│ …                            │
└──────────────────────────────┘
＋ 手动添加商品
本次消费小计 / 待分账金额
```

“记录消费”直接打开拍照或相册选择。识别成功后，所有有效条目、金额与一致的币种自动填入本页；用户无需逐件确认。识别失败、没有小票或识别不完整时，用户在同页继续手动添加或修改。

商品位于一个连续的账本行容器中：未编辑条目一行展示名称、金额和分配说明；点击任一条目，只有该条临时展开为名称、金额和二人分配编辑区。多项批量分配只在用户点击“批量编辑”后出现选择控件；商品标题下方显示浅色页内工具条（已选数量、分配方式、应用、完成），普通浏览状态不出现开关或深色大块表单。

小计位于清单尾部，固定表达“这笔消费识别或手工录入的总额”；它不遮挡新增商品、保存或分账操作。

### 3. 结算：独立的收尾动作

结算页只呈现本次旅行的应付/应收、转账建议、版本发布和分享链接。它不承载编辑商品或修改消费的职责。未产生转账时给出明确说明，仍允许发布当前结算版本。

## 交互与状态

- 自动识别统一币种时，自动更新本次消费币种；识别出混合币种时，保留当前币种并明确提示用户确认。
- 识别或上传失败时，保留照片、已填商品和手动入口，状态文案说明失败原因与下一步。
- 保存成功后回到旅行详情，新的消费摘要立即进入对应日期分组。
- 协作成员通过既有邀请链接加入；权限与后端规则沿用现状。
- 任何主操作保持明确动词：`拍小票，记录消费`、`手动添加商品`、`批量编辑`、`查看分账`、`发布结算版本`。

## 实现边界

- 优先复用现有页面、状态字段、API 和测试辅助函数；不引入 UI 组件库或新依赖。
- 先重构结构与 WXSS，必要时只在现有页面 JS 中补充交互状态。
- 保持现有小程序页面路由，避免影响邀请、OCR 回调和结算链接。

## 验收与测试

- 旅行详情：多笔消费保持紧凑，点击任意消费可进入编辑。
- 消费页：自动识别 8 项以上商品时，不出现逐项独立卡片；仅当前编辑行展开。
- 商品名称、金额和二人分配仍可编辑；批量编辑不会干扰普通点击。
- 单一币种识别能更新币种，混合币种保留手动确认。
- 结算、邀请、OCR 自动填充的既有测试继续通过；增加针对账本行展开与批量模式的前端测试。
