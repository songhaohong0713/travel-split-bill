# 协作权限与本地草稿设计

## 已确认目标

1. 旅行创建者与受邀成员都能查看旅行和消费记录。
2. 受邀成员可新建自己的消费，并仅能修改、删除自己创建的消费。
3. 旅行创建者可管理全部消费、邀请同行人、删除旅行和发布结算。
4. 新建消费在用户明确“保存”前只存在本机草稿，不创建空白服务端记录。

## 非目标

- 本阶段不重做旅行总览与只读消费详情。
- 不引入 RBAC 表或新依赖；沿用 `expenses.owner_id` 作为消费创建者归属。
- 不改变既有分账算法和汇率规则。

## 授权规则

| 操作 | 创建者 | 受邀成员 |
| --- | --- | --- |
| 查看旅行及全部消费 | 是 | 是 |
| 新建消费 | 是 | 是 |
| 修改/删除本人消费 | 是 | 是 |
| 修改/删除他人消费 | 是 | 否 |
| 邀请、删除旅行、发布结算 | 是 | 否 |

后端 API 与 CloudBase PostgreSQL RPC 均执行这些规则；前端仅根据权限调整入口显示。

## 草稿规则

- 新建手动消费或选择小票时，仅跳转到录入页；不调用创建消费 API。
- 录入页在未保存状态下，把可序列化表单内容按旅行保存在本机存储。
- 保存成功后清除该旅行的本机草稿；已保存消费不读取或覆盖草稿。
- 临时小票文件路径不作为跨会话可靠数据承诺；重新打开草稿时如图片已失效，用户可重新选择图片。

## 验收

- 新建后直接返回，旅行账本中不出现空白/未命名记录。
- 回到同一旅行的新建录入页，可恢复未保存的文本、条目、金额和分账信息。
- 成员访问他人消费的更新/删除 API 被拒绝；创建者仍可管理任意消费。
- 成员不能创建邀请或发布结算。
