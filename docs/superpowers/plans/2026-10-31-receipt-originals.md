# 小票原图持久化实施计划

> 执行方式：当前会话使用 executing-plans 逐项实施，保留工作区已有修改。

**Goal:** 小票保存后，两位旅行成员可以重新查看原图；历史缺图可补传，账目金额不受影响。

**Architecture:** 保留 FastAPI/JWT 上传入口，使用私有 CloudBase PG Storage 保存上传字节。数据库沿用 receipt_images / receipt_jobs / payload.receipt_job_id，原图可用状态使用 stored 区分旧版仅登记的 uploaded。查看接口先校验旅行成员和消费关联，再签发 5 分钟下载链接。小程序仅按需获取链接，不持久保存签名。

**Tech Stack:** Python 3.12、FastAPI、httpx、PostgreSQL、原生微信小程序。

## 全局约束

- 不修改用户开发者工具配置，不修改线上已有账目，不执行历史数据合并。
- 私有 receipts bucket；不开放 anon/authenticated 直接读写，不把 service_role key 交给客户端。
- 图片最大 5,000,000 字节，JPEG；文件保存成功后才标记 stored，识别失败保留文件。
- 补传跳过 OCR，保存时只改变 receipt_job_id，原消费金融字段原样保留。
- 删除后通过持久清理队列重试；不在数据库事务中假设对象存储与数据库原子提交。
- 云存储协议依据官方 storage.v1.postgres.openapi.yaml，使用当前 PG 模式，不使用旧 COS API。
