## 行为与平台说明

- 今天/未来为记录中，过去日期自动待转账；客户端附带时区偏移，服务器按客户端日历区分今天，旧客户端不带时使用 UTC。仍可手动结束今天记账。
- 已实际结清日期的新增、编辑、删除差额进入下一未结清日，显示补差额；目标日仍是今天时保持记录中，结束后计入待结清。转账金额、操作者、时间与撤销记录保留。
- 两人均可标记及撤销；合并转账的日页面仅显示分配给本日的金额，并注明合并转账；币种分开处理。
- 同行人未加入也显示两人平分预览。由于现有后端只允许真实成员 ID，保存双人分摊前需邀请加入；可明确选择自己承担 100% 后先保存，避免把虚构身份写入账务。
- 微信小程序没有任意打开微信聊天的接口。“打开微信”提供返回聊天完成转账的明确提示，复制金额正常执行，不自动发起付款。
- 历史计算快照不能证明真实转账。无法判断的旧账显示待转账，不自动设已结清；标记前仍需核对实际付款。
- 保留旧结算/识别页面文件以兼容旧路径，但新版流程不会进入旧录入区块或旧结算发布页。

## 旧旅行迁移

[操作说明](../../round2-trip-merge.md)。脚本先生成预览与摘要，再用摘要确认生成离线审阅包或带完整源数据校验和事务锁的 SQL，绝不自动执行。

地点相同、成员相同、币种相同、创建者相同、实际消费日期连续才候选。不同创建者、缺日期、账务冲突、邀请/分享记录等保守条件会阻止 SQL 生成，需要单独核对。所有源数据归档，实际支付、撤销、分配和消费明细在迁移演练中完整保留。含邀请/分享的真实历史旅行仍需处理对应权限后再迁移，不宣称可直接合并全部旧旅行。
