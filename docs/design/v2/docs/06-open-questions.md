## 3. 交接时补充的交互（可按产品意见调整）

- 撤销确认弹窗文案：「撤销结清？」/「这一天会回到待收款，并通知小周」
- 「保存并继续」：保存后回到拍照步骤，保留旅行和付款人
- 05 / 05b 有未保存修改时返回：弹窗「放弃这笔记录？」
- 商品行左滑删除；点商品行编辑名称、数量、金额
- 排序按钮文字跟随当前排序方式
- 01b：选排序即关闭弹层，切开关不关闭
- 首页「来自「东京」」在多段旅行时改为「来自 N 段旅行」
- 「复制账单」的文本格式（见 `01-business-rules.md` 第 8 节）

## 4. 需要产品决定

1. **已结清的那天再补记一笔**：建议自动回到待收款 / 待付款，只结算差额，并通知对方。
2. **超过两人的旅行**：当前 UI 和规则都按两人设计。多人时转账需要「最少转账次数」算法，分摊明细表和收款卡都要改。
3. **汇率来源**：需要选定接口（中间价还是银联 / Visa 汇率）以及缓存策略；离线时用最近一次缓存的汇率并标注日期。
4. **「进行中」的判断**：没填出行日期的旅行，是否按「最近 N 天内有记账」判断为进行中。
5. **时区**：旅行在东京、手机在北京时间时，「今天」按哪里算。建议按旅行所在地（可在旅行设置里选，默认取第一笔消费所在时区）。
