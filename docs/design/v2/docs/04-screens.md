## 01 首页 · `pages/home`

截图 `screens/01-home.png` · Figma `2004:24`

**目的**：一眼看到「别人欠我多少、我欠别人多少」，并快速记一笔。

**结构（从上到下）**
1. 问候：「下午好」（14 secondary，按时间切换）+ 大标题「下一笔，记到哪段旅程？」（28 Bold）。
2. 汇总卡（白，圆角 24，内边距 20）：
   - 「待收款」｜右侧「人民币结算」（纯文字，不可点）
   - 金额：「¥」22 Medium secondary + 「320.00」44 Bold
   - 「来自「东京」· 小周待付你」
   - 分隔线
   - 「你待付 ¥0.00 · 共 3 段旅行」
3. 列表标题「我的旅行」（17 Bold）+ 右侧排序按钮（白底胶囊，「出行日期」13 Medium + 排序图标 14）→ 点击打开 01b。
4. 旅行列表：TripCard × N（间距 12）。
5. 固定底部栏：主按钮「+ 记一笔」（撑满）+ 次按钮「新建旅行」（110 宽）。

**交互**
- 点旅行卡 → 03。「待邀请」卡 → 邀请分享。
- 「+ 记一笔」→ 拍照 / 选图（未设计）→ 识别 → 05，旅行默认选「进行中」的那段；没有进行中的旅行时默认最近一段，并在 05 里提示。
- 「新建旅行」→ 02b。
- 没有任何旅行时显示 02a。加载失败时显示 06。

## 01b 排序与筛选弹层

截图 `screens/01b-home-sort-sheet.png` · Figma `2015:54`

- 由排序按钮打开；打开期间排序按钮加 1.5px `brand/green` 描边。
- 排序（单选，默认第一项）：出行日期「最近的旅行在前」/ 最近记账「最近有新消费的在前」/ 待结清优先「有钱没算清的排在前面」。
- 筛选：「隐藏已结清的旅行」开关，下面一行说明已结清的数量（「已结清 1 段」）。
- 选中即生效并关闭弹层（开关切换不关闭）。「重置」恢复默认。选择存在本地。
- 排序按钮上的文字跟随当前排序方式变化（「出行日期」「最近记账」「待结清优先」）。

## 05 记一笔（确认） · `pages/expense-edit`（快速模式）

截图 `screens/05-add-expense.png` · Figma `2004:439`

**入口**：拍小票识别成功后。手动记账时同一页面，但没有顶部识别标签，金额为空并自动聚焦。

**结构**
1. 识别行：浅绿胶囊「✓ 已识别小票，请核对」｜右侧链接「查看小票原图」→ 图片预览（`wx.previewImage`）。
2. 金额卡（AmountDisplay）：店名「药妆店 ✎」；「1,280 [JPY ▾]」；「≈ ¥54.22 · 汇率 1 JPY = 0.04236 CNY」。点金额 → 数字键盘编辑；点币种 → 币种选择。
3. 字段卡：
   - 旅行：「东京 进行中 ▾」→ 选择旅行
   - 日期：DateChips；右侧「与小票日期一致」
   - 付款人：「我 ▾」
   - 分摊：分段控件「平分 / 自定义」+ SplitSummary（我 640 JPY ≈ ¥27.11 / 小周 640 JPY ≈ ¥27.11 / 「你付了全部 1,280 JPY，小周应还你 ¥27.11」）
4. 「更多选项」卡：「商品明细（已识别 1 项）· 账单调整」+ ▾ → 展开为 05b 的完整版。
5. 固定底部：说明「保存后记入「东京 · 10月8日」账单」+「保存并继续」（次，132 宽）+「保存」（主）。
   - 保存 → 回到来源页并提示「已记入 10月8日」。
   - 保存并继续 → 保存后清空表单，回到拍照步骤，旅行和付款人保持不变。

**离开确认**：有未保存修改时点返回，弹窗「放弃这笔记录？」。

## 05b 记一笔（详细 · 按商品分摊）

截图 `screens/05b-add-expense-detailed.png` · Figma `2016:85`

与 05 是同一个页面的展开态（替代旧版「录入消费」页）。差异：

1. 分摊分段控件选「按商品」，字段卡里不再显示分摊预览。
2. **商品明细卡**：「商品明细」｜「已识别 5 项」；说明「点商品名旁的标签，切换「平分 / 我的 / 小周的」」；ItemRow × 5（化妆水 我的 1,280 / 面膜 平分 836 / 润唇膏 小周的 528 / 卸妆巾 平分 220 / 购物袋 平分 100）；底部「+ 添加商品」｜「合计 2,964 JPY」。点商品行（非标签区域）编辑名称、数量、金额；左滑删除。
3. **本笔分摊卡**：「本笔分摊」｜「按商品计算」；SplitSummary：我（付款人）1,858 JPY ≈ ¥78.71 / 小周 1,106 JPY ≈ ¥46.85 /「你付了全部 2,964 JPY，小周应还你 ¥46.85」。
4. **汇率与实际扣款卡**：
   - 「汇率」｜「1 JPY = 0.04236 CNY ✎」；下一行「10月8日 中间价 · 点右侧数字可修改」
   - 分隔线
   - 「实际扣款（可选）」输入框，占位「信用卡账单上的人民币金额」，后缀「元」；说明「填写后按实际扣款折算，手续费两人按比例分担」
5. **账单调整**入口行：「账单调整 / 折扣、免税、优惠券、小费」｜「+ 添加」（调整项编辑页**未设计**）。
6. 底部说明带上结论：「保存后记入「东京 · 10月8日」· 小周应还你 ¥46.85」。

金额卡第三行在此模式下写「≈ ¥125.56 · 汇率见下方」。

## 06 异常 · 首页（登录未完成）

截图 `screens/06-error-login.png` · Figma `2004:517`

- 触发：登录失败或首页数据加载失败（网络错误、`wx.login` 失败、接口超时）。
- 问候和标题保持不变。
- 错误提示条：「暂时无法加载你的旅行 / 网络或登录异常，已记录的账单不会丢失」+「重试」。
- 下面 3 张骨架卡占位（有本地缓存时直接显示缓存的旅行，不显示骨架）。
- 底部说明「恢复后会自动合并，不会重复」+ 次按钮「仍要先新建旅行」→ 02b（离线创建，规则见 01 第 8 节）。
- **不要**在这里显示「还没有旅行账单」，老用户会以为数据丢了。
